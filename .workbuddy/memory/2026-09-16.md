## 搭建 GitHub Actions CI/CD

分析项目架构后重写/新建三套工作流：

- `.github/workflows/ci.yml`（重写）：PR/push main 触发，两个 job —— 用户脚本（语法 + 元数据校验 + 单元测试）、展示站（typecheck + 条件 lint + build）。
- `.github/workflows/cd.yml`（新建）：push main 静态导出 Next.js 站并部署 GitHub Pages，同时把 userscript 复制到 `out/` 提供稳定分发地址。
- `.github/workflows/release.yml`（新建）：push tag `v*` 校验 tag/脚本 `@version`/CHANGELOG 三者一致后创建 Release 并上传脚本。

配套新增/修改：

- `scripts/validate-userscript.mjs`：userscript 静态校验器（元数据完整性、semver、@match 覆盖、`@grant` 与代码实际 GM_* 使用双向一致、debugger、第三方外链告警、版本与 CHANGELOG 一致）。零新增依赖。
- `tests/userscript.test.mjs`：node:test 内置 runner，10 个用例（含 3 个校验器自测）。
- `postcss.config.mjs` + `@tailwindcss/postcss`：Tailwind v4 必须显式声明 PostCSS 插件，否则 next build 必挂。
- `next.config.mjs`：`NEXT_STATIC_EXPORT=true` 时才 `output: 'export'`，避免影响本地 dev/start；CI 下自动加 basePath `/Gemini-Quota-Monitor`。
- `package.json`：新增 `typecheck` / `test` / `validate:script`；`test` 用 `node --test "tests/**/*.test.mjs"`（目录模式在本机 Windows 会 MODULE_NOT_FOUND，glob 由 Node 自己展开才跨平台）。
- `.gitignore`：补 `.next` / `out` / `*.tsbuildinfo` / `next-env.d.ts`。
- `docs/DEVELOPMENT.md`：补充 CI/CD 表格与发布流程。

## 关键结论与环境坑

- 项目是**双产物**：userscript（核心交付，经 raw main 分支分发，合入即推给所有用户）+ Next.js 15 展示站（纯客户端，可静态导出）。CI 必须同时覆盖两者。
- 版本三处不一致（现存问题，未擅自改）：脚本 `@version` 2.0.0、CHANGELOG 最新 1.8.3、package.json name 内嵌 v1.8.3。release 工作流会强制校验，需人工对齐。
- 本机 Windows 上 `next build` 无法验证：`@next/swc-win32-x64-msvc` 报 not a valid Win32 application；另 npm install 曾超时中断导致 lucide-react/framer-motion 部分文件缺失（重装后恢复，非项目依赖问题，CI 上 npm ci 不受影响）。判断 Windows 构建报错时先排查这两类环境问题。
- npm 走官方源极慢，本机可用 `--registry=https://registry.npmmirror.com`；但生成的 package-lock.json 会把镜像地址写进 resolved，需 sed 替换为 registry.npmjs.org 后再提交。
- 仓库原有 bun.lock，本次新增 package-lock.json（CI 用 npm）。两套 lock 并存需在后续维护中注意同步。
